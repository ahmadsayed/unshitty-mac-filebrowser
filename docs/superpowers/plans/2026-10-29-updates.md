# Check for Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A manual "Check for Updates…" that installs signed updates for the AppImage and the macOS app after the user approves, and points `.deb`/`.rpm` users to the package manager.

**Architecture:** `tauri-plugin-updater` reads `latest.json` from the newest published GitHub release. A plain Rust module (`updates.rs`) decides the install kind, classifies failures and guards against two installs at once; four `async` commands in `lib.rs` wrap the plugin. `src/updates.ts` runs the dialogs with `openDialog`. The release workflow signs the updater files when the key secret is present and `scripts/updater-manifest.mjs` writes `latest.json`.

**Tech Stack:** Rust + Tauri 2 + `tauri-plugin-updater` v2, TypeScript, Vitest + jsdom, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-29-updates-design.md`

## Global Constraints

- Manual only: no network request except when the user picks "Check for Updates…".
- Endpoint: `https://github.com/ahmadsayed/unshitty-mac-filebrowser/releases/latest/download/latest.json`.
- Self-update only for `AppImage` and `MacApp`; never for `LinuxPackage` or `DevBuild`.
- `bundle.createUpdaterArtifacts` stays off in `tauri.conf.json`; only CI turns it on.
- The private signing key and its password are the maintainer's. Agents never generate, read, print or store them.
- Exact wording comes from the spec's two tables. "Not Now" is the default response when an update is offered.
- New crate: `tauri-plugin-updater` only. `Cargo.lock` gains only its entries. No new npm package; the frontend calls our commands, not `@tauri-apps/plugin-updater`.
- Commands are `async fn`; no long work on Tauri's shared async workers.
- Every new command has a mock in `dev/mock-tauri/core.ts` and a case in `tests/mock-core.test.ts`.

**One deliberate split from the spec:** `updates.rs` classifies failures into a kind, and the frontend holds the wording, like every other message in the app.

## Review Focus

1. **Cancel, then Try Again or Download and Install again:** must start a new download, not fail with "already running". Pinned by the `InstallGuard` test (Task 1) and a frontend test (Task 2).
2. **Esc or closing the dialog during a download:** must cancel the download; nothing gets installed afterwards behind the user's back. Frontend test in Task 2.
3. **An operation starts after "is installed" appears:** Restart Now must disable again, then re-enable when the operation ends. Frontend test in Task 2.
4. **A network failure during the download (not during the check):** shows "The download failed." with Try Again, not the check-failed dialog. Frontend test in Task 2.
5. **A release where one platform's `.sig` is missing:** Mac users would get an unreadable "Could not check" forever. The manifest script must fail the release job instead of writing a partial `latest.json`. Script test in Task 3.

### Task 1: Backend: install kind, failure kinds, commands

**Files:**
- Create: `src-tauri/src/updates.rs`
- Modify: `src-tauri/src/lib.rs` (`mod updates;`, plugin registration next to `tauri_plugin_opener::init()` ~1565, four commands, `generate_handler!` ~1621, managed state)
- Modify: `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, `src-tauri/tauri.conf.json`, `src-tauri/capabilities/*.json` only if the plugin's init requires it (it shouldn't: we grant the webview no updater permissions)

**Interfaces:**
- Produces in `updates.rs` (no Tauri types):
  - `#[derive(Serialize, Clone, Copy, PartialEq, Debug)] #[serde(rename_all = "snake_case")] pub enum InstallKind { AppImage, MacApp, LinuxPackage, DevBuild }`
  - `pub fn install_kind(debug: bool, os: &str, appimage: Option<&str>) -> InstallKind` (`os` as in `std::env::consts::OS`)
  - `pub fn can_self_update(kind: InstallKind) -> bool`
  - `#[serde(rename_all = "snake_case")] pub enum FailureKind { Offline, Unverified, NoPermission, Failed }`
  - `#[derive(Serialize)] pub struct Failure { pub kind: FailureKind, pub detail: String }`
  - `pub fn classify(source: FailureSource, detail: String) -> Failure`. `FailureSource` is a small enum (`Network { connect: bool }`, `Signature`, `Io(std::io::ErrorKind)`, `Other`) that `lib.rs` builds from the plugin's error. Connect or DNS errors give `Offline`, `Signature` gives `Unverified`, `Io(PermissionDenied | ReadOnlyFilesystem)` gives `NoPermission`, and everything else gives `Failed`.
  - `pub struct InstallGuard` with `fn try_start(&self) -> bool` (false while one runs) and `fn finish(&self)`. Interior `AtomicBool`.
- Produces in `lib.rs` (the commands return `Result<_, Failure>`, so the frontend gets `{ kind, detail }` as the error):
  - `check_update() -> UpdateInfo { current: String, latest: Option<String>, kind: InstallKind, release_url: String }`. `release_url` is `https://github.com/ahmadsayed/unshitty-mac-filebrowser/releases/tag/v<latest>`, or `…/releases/latest` when up to date.
  - `install_update(on_progress: Channel<UpdateProgress>)`, where `UpdateProgress { phase: "downloading" | "installing", downloaded: u64, total: Option<u64> }`.
  - `cancel_update()`: aborts the running install task's download. It's a no-op when nothing runs.
  - `restart_app()`

- [ ] **Step 1: Write the failing tests in `updates.rs`**

- `install_kind_for_each_environment`:
  - `(true, "linux", Some("/x.AppImage"))` gives `DevBuild`
  - `(false, "macos", None)` gives `MacApp`
  - `(false, "linux", Some("/home/me/.local/bin/file-browser.AppImage"))` gives `AppImage`
  - `(false, "linux", Some(""))` gives `LinuxPackage`
  - `(false, "linux", None)` gives `LinuxPackage`
- `only_appimage_and_mac_update_themselves`: `can_self_update` is true for exactly `AppImage` and `MacApp`.
- `failures_are_classified`: `Network{connect:true}` gives `Offline`, `Signature` gives `Unverified`, `Io(PermissionDenied)` gives `NoPermission`, `Io(ReadOnlyFilesystem)` gives `NoPermission`, `Network{connect:false}` gives `Failed`, `Other` gives `Failed`. The detail is kept verbatim.
- `the_guard_allows_one_install_at_a_time` (Review Focus 1): `try_start()` is true, a second `try_start()` is false, then after `finish()` it's true again.
- `failure_serializes_for_the_frontend`: `serde_json::to_value(Failure{Offline,"x"})` equals `{"kind":"offline","detail":"x"}`, and `InstallKind::AppImage` serializes to `"app_image"`.

- [ ] **Step 5: Add the plugin, config and commands**

- `Cargo.toml`: `tauri-plugin-updater = "2"`. Check that the `Cargo.lock` diff only adds entries.
- `tauri.conf.json`: `plugins.updater = { "pubkey": "<from Task 0>", "endpoints": ["<Global Constraints URL>"] }`. Leave `createUpdaterArtifacts` alone.
- `lib.rs`:
  - register `tauri_plugin_updater::Builder::new().build()`.
  - manage `UpdateState { guard: InstallGuard, task: Mutex<Option<tauri::async_runtime::JoinHandle<()>>>, pending: Mutex<Option<tauri_plugin_updater::Update>> }`. `check_update` stores the `Update` it found in `pending`, so `install_update` doesn't check again.
  - `install_update` returns `Failed` with detail "No update to install." when nothing is pending, and refuses (`Failed`, "An update is already being installed.") when the guard is busy.
  - It spawns the download in a task: `update.download(on_chunk, on_finish)` sends `downloading` progress; then it sends `installing` and runs `update.install(bytes)`.
  - It awaits the task. An abort maps to `Failed` with detail "Cancelled.", which is the existing `CANCELLED` string in `operations.ts`.
  - `finish()` runs on every path.
  - It refuses unless `can_self_update(install_kind(cfg!(debug_assertions), std::env::consts::OS, std::env::var("APPIMAGE").ok().as_deref()))`.
- A plugin error becomes `updates::classify(...)` through a small `fn failure_from(e: tauri_plugin_updater::Error) -> Failure` in `lib.rs`. It matches the plugin's variants; for a `reqwest` error, check `is_connect()` / `is_timeout()`.

**Files:**

**Interfaces:**
- Produces in `scripts/updater-manifest.mjs`:
  - `export function buildManifest(files: string[], readSig: (path: string) => string, opts: { version: string; tag: string; repo: string; notes: string; pubDate: string }): object | null`
  - A CLI: `node scripts/updater-manifest.mjs <packages-dir> <out.json>`. It reads the version from `package.json`, the tag from `GITHUB_REF_NAME`, and the repo from `GITHUB_REPOSITORY`. It exits 0 without writing anything when there are no `.sig` files, and exits 1 with a message when the set is incomplete.
