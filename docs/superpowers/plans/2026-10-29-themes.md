# Themes (GNOME + macOS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A theme choice (Automatic / GNOME / macOS) that restyles the app instantly, with a macOS 26 Tahoe look as the default on a Mac.

**Architecture:** `<html data-theme="gnome|macos">` selects a set of CSS tokens from `src/themes/gnome.css` or `src/themes/macos.css`; `src/styles.css` keeps the structure and reads tokens. The few layout sizes the virtualized views compute in JavaScript come from a per-theme table in `src/theme.ts`. `applyTheme()` in `src/main.ts` sets the attribute and relays out the view.

**Tech Stack:** TypeScript + Vite, plain CSS, Vitest + jsdom, Playwright for screenshots. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-29-themes-design.md`

## Global Constraints

- Themes change only the look. Behaviour, wording, shortcuts, dialog button order and default responses stay GNOME's in both themes.
- `prefs.theme`: `"auto" | "gnome" | "macos"`, default `"auto"`; `"auto"` → `macos` when `isMac`, else `gnome`.
- Menu block between "Show Thumbnails" and "Keyboard Shortcuts": heading "Theme", radio items "Automatic", "GNOME", "macOS".
- Every colour is a token with a light and a dark value, in both themes.
- No Apple assets: system font via `-apple-system`, then `"Inter"`, then `"Adwaita Sans"`.
- macOS accent `#007AFF` light, `#0A84FF` dark.
- Layout table: GNOME list padding 12, min row 34, header 35, grid pad 12, gap 6; macOS 8, 24, 28, 12, 6.
- The GNOME theme stays pixel-identical to `main`.
- Virtualization rules hold: no rendering all of `shown`, no `getBoundingClientRect` hit-testing, `scrollToIndex` not `scrollIntoView`.
- Run git and scripts as plain commands (AGENTS.md); never `--no-verify`.

## Review Focus

1. **Saved pref is garbage** (`"theme": "solarized"` or a number in localStorage): expect the Automatic behaviour, not a blank `data-theme`. Test in Task 2.
2. **Switching while scrolled deep into `/big` (10,000 entries) in list view:** the first visible item stays at the top; no jump to the start. Test in Task 2.
3. **Switching in grid view:** the grid sizes are equal in both themes, so the column count and positions don't change. Test in Task 2.
4. **localStorage unavailable** (the getter throws): the theme still resolves to Automatic and the menu still switches the current window. Test in Task 2.
5. **A `storage` event for an unrelated key, or `prefs` with the same theme:** no relayout and no closed popover. Test in Task 2.

- [ ] **Step 4: Wire it into `src/main.ts`**

- `prefs.theme = "auto" as ThemeChoice`.
- `let currentTheme: Theme`. `applyTheme()` computes `resolveTheme(prefs.theme, isMac)` and returns early if it's unchanged and the attribute is already set. Otherwise it sets `document.documentElement.dataset.theme`, notes the first visible index (from `scrollTop`, `layout.bodyTop`, `layout.padY` and the pitch), runs `relayout()`, sets `scrollTop` so that index is at the top again, then `renderWindow(true)`.
- `init()` calls `applyTheme()` right after `loadPrefs()`, before anything renders. That's the existing spot next to `platform-mac`.
- `computeLayout()` reads `LAYOUT_SIZES[currentTheme]`. Remove `GRID_PAD`, `GRID_GAP` and `LIST_HEADER_H` as constants, and update their other uses to read the table too.
- `openMainMenu()` gets the block: `{ separator: true }`, `{ heading: "Theme" }` (an existing `MenuItem` variant in `ui.ts`), then three radio items whose action sets `prefs.theme`, calls `savePrefs()` and `applyTheme()`.
- In `init()`: `window.addEventListener("storage", …)`. For `key === "prefs"`, run `loadPrefs()`. If `resolveTheme(prefs.theme, isMac) !== currentTheme`, call `closePopover()` and then `applyTheme()`.

- [ ] **Step 1: Write `src/themes/macos.css`**

Token values under `:root[data-theme="macos"]` (light) and the same selector inside `@media (prefers-color-scheme: dark)`, covering every token `gnome.css` defines. Then rules scoped to `[data-theme="macos"]`, one commented group per spec paragraph:

- **Toolbar:** headerbar background transparent with no shade; the view scrolls under it (`.view-scroll` gets top padding equal to `--headerbar-height`, and the headerbar is positioned over it). - **Files:** `--font: -apple-system, "Inter", "Adwaita Sans", system-ui, sans-serif`, `--font-size: 13px`; accent `#007AFF` / `#0A84FF`. Grid selection: a grey rounded box on the icon, a blue pill with white text on the name. List: 24 px rows, alternating stripes (`:nth-child` can't be used on virtualized rows, so stripe by `data-index` parity, set as a class in `itemHtml` if it isn't there already), a solid blue selected row with white text, a smaller and lighter header.
- **Menus and popovers:** glass, 12 px radius, `.popover-arrow` hidden, 24 px items, blue full-width hover highlight with white text.
- **Dialogs, toasts, banners:** dialogs at 24 px radius with capsule buttons; toasts as glass capsules; banners inset with rounded corners.
- **Linux window controls** under the macOS theme: small round buttons.
